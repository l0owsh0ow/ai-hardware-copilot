# AI 补充元器件（带来源溯源）技术方案

> 状态：待评审。判断结论：**可以，但必须分层设计**——库内=已验证，库外=附来源。

## 一、核心原则：分层可信

| 类型 | 信任模型 | 界面表现 |
|------|---------|---------|
| 库内元器件 | 已验证（Datasheet 在库，防幻觉三层照旧） | 原徽章（最佳匹配/推荐/可选） |
| AI 补充元器件 | **附来源**（必须有信息来源链接，否则丢弃） | "AI 补充·来源待核"徽章，置信度上限 0.85 |

防幻觉承诺升级为：**库外型号必须有可核实来源，否则不推**。

## 二、数据模型扩展

```python
class Component:
    ...
    source: str = "knowledge_base"   # knowledge_base | ai_supplement
    source_urls: list[str] = []      # 非库候选必填
```

## 三、推荐流程：两阶段

1. 第一阶段（不变）：现有知识库检索 Top5
2. 第二阶段（新增）：候选不足/用户需要时，允许 LLM 补充：
   - 每个补充候选**必须附 ≥1 个来源链接**（厂商官网/立创商城/DigiKey）
   - 验证层：无来源 → 丢弃；可选 URL 可达性检查（HTTP 200）
   - 补充候选置信度上限 0.85，不参与"最佳匹配"

## 四、前端表现

- "AI 补充·来源待核"徽章（区别于库内徽章）
- 推荐理由尾部附"信息来源"链接
- 提示文案：参数由 AI 提取，请以 Datasheet 为准

## 五、明确不做

- AI 补充元器件**不自动入库**，须人工审核后才写入知识库（两个闸门：补充≠入库）

## 六、演进路径（风险诚实说明）

| 阶段 | 方案 | 风险 | 建议 |
|------|------|------|------|
| 第一步（现在可做） | LLM 直接生成补充候选 + 强制来源 | LLM 可能编造来源链接 | 三重控制：必填来源 + 置信度降级 + 提示核实；临时方案 |
| 第二步（V2 正解） | 联网检索/商城搜索 → LLM 从真实结果选 | 需要搜索 API/抓取，有成本 | 相当于 RAG 扩展到互联网，幻觉风险大幅降低 |

## 七、产品意义

- 回答"100 个元器件不够"：双轨方案 = 扩充知识库（提质）+ AI 补充带溯源（扩覆盖）
- 把"可信"从"我们保证真实"升级为"告诉你依据，你可以自己核实"

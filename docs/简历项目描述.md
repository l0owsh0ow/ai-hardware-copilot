# 简历项目描述（PM 岗）

> 目标：把 AI 硬件选型助手包装成"能体现产品经理能力"的简历项目。
> 原则：不吹商业成果，重点展示**思考过程、决策质量、落地能力、复盘意识**。

---

## 一、项目定位（一句话）

**AI 硬件选型助手**：面向电子专业学生的 AI 选型工具——针对"新手不会选元器件、不信任 AI 推荐"的问题，用自然语言输入 + RAG 防幻觉 + BOM 闭环，从 0 到 1 完成需求分析、产品设计、MVP 开发与迭代。

## 二、简历项目经历（可直接使用）

**AI 硬件选型助手｜产品经理 + 全栈开发（个人项目）**

针对电子专业学生"不知道选什么元器件、ChatGPT 推荐不可信"的痛点，设计并落地 AI 选型工具：学生用自然语言描述需求，系统解析参数、基于 100 个真实元器件的知识库做防幻觉推荐（附理由/价格/Datasheet），一键生成并导出 BOM。

- 需求与调研：完成立创/DigiKey/ChatGPT 竞品分析，拆解"参数筛选器门槛高"的四个层次（知识/语言/翻译/判断），定位差异化：翻译层交给 AI，信任层用可核实的 Datasheet 兜住
- 产品设计：设计四步引导流（输入→参数确认→推荐→BOM）；关键决策含参数确认页可编辑（信任）、免登录（降低流失）、Top5+匹配度（决策负担最小化）、MVP 砍登录/对比（优先级）
- 数据与迭代：20→100 个元器件，实测定位并修复向量检索品类失衡、12V 电压误杀 MCU、接口硬过滤过严等问题；视觉从初版迭代到商业级
- 验证意识：设计北极星指标（输入→BOM 完成率）与埋点漏斗，规划 10 人校园可用性测试

## 三、面试口头讲述版（1 分钟）

> "我发现电子专业学生选型靠师兄推荐、碰运气：参数筛选器门槛太高，ChatGPT 又会编型号。所以我的产品解决两个问题——把'学会选型'降级成'说人话'，用 RAG 三层防幻觉保证只推真实型号并附 Datasheet 可核实。我独立完成了调研、产品设计、开发到迭代，核心决策包括参数确认页可编辑来建立信任、MVP 砍掉登录来降低流失。我清楚自己的局限：没有规模化用户，所以我设计了北极星指标和埋点漏斗，下一步就是 10 人校园可用性测试。"

## 四、加分素材库（面试按需引用）

| 决策 | 背后的产品思考 |
|------|--------------|
| 参数确认页可编辑 | AI 会错，让用户能纠正 = 信任机制 |
| 免登录 | 注册是学生流失最大坎，MVP 验证核心价值优先 |
| 推荐 Top5 + 匹配度徽章 | 决策负担最小化，信息分层 |
| 先 100 个元器件 | 先验证流程再谈规模，数据质量 > 数量 |
| 靛蓝视觉迭代 | 从"可用"到"专业感"的设计演进 |
| 历史记录不消耗 token | 关注真实用户诉求（节省）并转化为产品设计 |
| DeepSeek → 本地模型 | 成本意识 + 技术选型权衡 |

## 五、还差什么（建议补齐，成本低、加分高）

1. **3-5 份真实访谈/问卷**：同学群里发问卷，拿到真实反馈 → 简历写"访谈 5 名电赛学生验证痛点"
2. **版本迭代日志**：把每次决策写成版本记录（v0.1 规则解析 → v1.0 DeepSeek → v1.1 本地模型）
3. **指标框架文档**：北极星 + 漏斗 + 假设清单（已有素材，汇总成一页）

## 六、避免踩的坑

- ❌ 不要写"预计市场规模 X 亿"（没数据支撑，面试官会追问）
- ❌ 不要写"用户反馈良好"（没真实用户）
- ✅ 写"我设计了如何验证"（诚实且有方法）
- ✅ 写具体决策和数字（100 个、Top5、20→100、四步流）

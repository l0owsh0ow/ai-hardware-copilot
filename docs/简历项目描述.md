## 二、简历项目经历（可直接粘贴）

**AI 硬件选型助手｜产品经理 + 全栈开发（个人项目）**

针对电子专业学生"不知道选什么元器件、不信任 AI 推荐"的痛点，从 0 到 1 完成调研、设计、开发与迭代：学生用自然语言描述需求，系统解析参数、基于 100 个真实元器件的知识库做防幻觉推荐（附理由/价格/Datasheet），一键生成并导出 BOM。

- **需求与调研**：拆解立创/DigiKey/ChatGPT 竞品，定位"参数筛选器门槛高"的四个层次（知识/语言/翻译/判断），确定差异化——翻译层交给 AI、信任层用可核实的 Datasheet 兜住
- **产品设计**：四步引导流（输入→参数确认→推荐→BOM）；关键决策：参数确认页可编辑（信任）、免登录（降流失）、Top5+匹配度（决策负担最小化）、MVP 砍登录/对比（优先级）
- **工程与迭代**：独立实现前后端全栈（Next.js + FastAPI + RAG + LLM）；20→100 元器件；实测定位并修复向量检索品类失衡、电压过滤误杀、接口硬过滤过严等 5+ 个真实问题；接入 DeepSeek 与本地 GLM-4-9B 双模式
- **安全与运营**：落地 P0 安全底线（Token 鉴权/限流/降级链/Key 管理）+ P1 运营能力（埋点分析、知识库管理后台、数据看板、反馈入口）
- **数据意识**：定义北极星指标（输入→BOM 完成率）与核心漏斗，埋点落地；规划 10 人校园可用性测试作为下一步验证

## 三、产品全貌

### 3.1 用户与痛点

| 用户 | 场景 | 痛点 |
|------|------|------|
| 高校电子专业学生（核心） | 课程设计/电赛/毕设 | 不会选型、看不懂参数、预算敏感 |
| 硬件爱好者（次核心） | 个人项目 | 效率低、对比繁琐 |
| 硬件课程老师（潜在） | 教学 | 难以给学生结构化建议 |

**核心洞察**：选型是"信任成本极高"的决策——买错元件浪费钱和时间；学生靠"师兄推荐"碰运气，AI 又不可信。

### 3.2 核心流程（全链路）

```
自然语言需求 → LLM 解析为结构化参数 → 用户确认/修改
  → 向量+关键词双路检索 Top 30 → 结构化过滤（电压/接口/品类）
  → LLM 从候选中排序+写理由 → SQLite 交叉验证 → Top5 推荐
  → 用户选择 → 一键生成 BOM → 导出 Excel/CSV
```

### 3.3 功能清单

| 功能 | 说明 |
|------|------|
| 需求输入 | 示例快捷填充、可选参数表单、Ctrl+Enter、字符计数 |
| 参数确认 | 8 个参数卡片可编辑，AI 可被纠正（信任机制） |
| 推荐结果 | 匹配度徽章、推荐理由、价格/库存/Datasheet/采购链接同卡 |
| 筛选排序 | 品类筛选、匹配度升降序 |
| BOM | 数量修改实时算总价、Excel/CSV 导出（含数量覆盖） |
| 历史记录 | 每次问题+结果自动存档，**查看零 token**，可删除/清空 |
| 个人主页 | 配置 LLM 供应商（本地/DeepSeek/OpenAI/Claude/自定义）+ 测试连接 |
| 管理后台 | 元器件增删改查、重建索引、数据看板 |

## 四、技术架构（面试深挖用）

| 层 | 技术 | 为什么 |
|----|------|--------|
| 前端 | Next.js 14 + React + TypeScript + TailwindCSS | 组件化、类型安全、移动端适配 |
| 后端 | Python + FastAPI + Pydantic | AI 生态、自动文档、数据校验 |
| AI | DeepSeek（云端）/ GLM-4-9B（本地 Ollama） | 质量与成本的权衡，双模式可切换 |
| 检索 | ChromaDB + sentence-transformers（384 维中文向量） | 语义检索，"认意思不认字" |
| 防幻觉 | RAG 三层：候选约束/交叉验证/数据以库为准 | 保证只推真实型号 |
| 数据 | SQLite（事实源）+ JSON（源数据）+ 向量库 | 双库分工：向量管找、关系库管真 |
| 降级 | LLM 失败→规则模式，响应带 degraded 标识 | 保证服务可用性 |

## 五、产品决策库（面试最值钱的部分）

| 决策 | 思考 | 级别 |
|------|------|------|
| 参数确认页可编辑 | AI 会错，让用户能纠正 = 信任 | 高级 |
| 免登录 | 注册是学生流失最大坎，MVP 验证核心优先 | 高级 |
| 推荐 Top5 + 匹配度 | 决策负担最小化，信息分层 | 中级 |
| 先 100 个元器件 | 先验证流程再谈规模，数据质量 > 数量 | 高级 |
| RAG 而非纯 LLM | 防幻觉是选型产品的生命线 | 高级 |
| 向量+关键词双路 | 纯向量会品类失衡（实测踩坑） | 高级 |
| 双 AI 模式 | 云端质量 + 本地零成本，用户可切换 | 中级 |
| 历史记录零 token | 响应真实用户诉求（省）并转化为设计 | 中级 |
| 管理后台+埋点 | 产品要"可运营、可测量"而非能跑 | 高级 |
| 靛蓝视觉迭代 | 从"可用"到"专业感"的设计演进 | 初级 |

## 六、安全与运营（体现"商业级思维"）

### P0 安全底线（全部落地）

| 项 | 实现 |
|----|------|
| 接口鉴权 | 所有 API 需 X-API-Token，防匿名滥用 |
| 速率限制 | LLM 接口 10 次/分/IP，防成本失控 |
| 降级链 | LLM 失败→规则模式→友好提示（degraded 标识） |
| Key 安全 | .env/.env.local 均 gitignored，不入库 |
| 免责声明 | 页脚数据来源/价格免责/反馈入口 |

### P1 运营能力（全部落地）

- **埋点分析**：10+ 事件类型自动上报，数据看板可视化漏斗
- **知识库管理后台**：元器件 CRUD + 重建向量索引
- **结构化日志**：请求方法/路径/状态/耗时
- **反馈入口**：页脚邮件反馈 + 缺失元器件提交

## 九、面试话术

### 30 秒版

> "我做了一个 AI 硬件选型助手：学生用大白话描述需求，AI 解析参数、从 100 个真实元器件的知识库做防幻觉推荐（附理由/价格/Datasheet），一键生成 BOM 并导出。核心解决三个问题：新手看不懂参数筛选器、ChatGPT 会编型号、选完型还要手动做物料清单。"

### 1 分钟版（含信任与迭代）

> "市面上选型工具分两类：筛选器门槛高，ChatGPT 能聊但会幻觉。我用 RAG 让 AI 只能从知识库选、型号回数据库交叉验证、附可核实的 Datasheet，把'可信'做成工程承诺。我从规则模式迭代到 DeepSeek，再接入本地模型实现零成本；过程中修过向量检索品类失衡等真实问题，最后补上了安全底线和埋点分析，让它从'能跑的 demo'变成'可运营、可测量的产品'。"
